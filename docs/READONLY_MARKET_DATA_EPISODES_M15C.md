# M15C — Read-Only Market Data + Fresh Paper-Trading Episodes

M15C adds bounded market-data acquisition and repeated fresh-snapshot paper
trading to the canonical VN97 trading path.

It does **not** add broker credentials, live-money order authority, a second
trading model, a parallel planner, or a cloud AI backend.

## Canonical path

```text
trusted app/user endpoint configuration
  -> HTTPS GET only
  -> bounded VN97MKTFEED1 parser
  -> VN97MKT1 snapshot
  -> canonical VN97 M15B reasoning
  -> exact HOLD / ORDER contract
  -> M15A deterministic paper risk engine
  -> VN97TRD1 journal
```

## Read-only network boundary

`VN97HttpsMarketDataTransport` is deliberately narrow:

- HTTPS only;
- GET only;
- no request body;
- no URL user-info;
- no redirects;
- bounded connect/read timeouts;
- bounded response bytes;
- compressed content is rejected;
- cleartext traffic remains disabled in the Android application.

The endpoint is trusted application/user configuration. It is not generated by
VN97 cognition and is not treated as model authority.

## VN97MKTFEED1

The network response is not arbitrary market prose. It must use the strict text
format:

```text
VN97MKTFEED1
source=fixture.market
observed_ns=1000000000
Q|ABC|99000000|100000000|999000000
Q|XYZ|49000000|50000000|999000000
```

The configured policy controls exact source ID, an explicit symbol allowlist,
response size, observation age, quote age, connect timeout, and read timeout.

Malformed UTF-8, unknown symbols, stale/future observations, stale quotes,
duplicate symbols, invalid prices, excessive quote counts, or source mismatch
fail closed before cognition.

## Repeated episode invariant

`VN97PaperTradingEpisodeRunner` is caller-driven and bounded. It does not
silently create a permanent background trader.

Each `runNext(nowNs)`:

1. enforces the episode-attempt budget;
2. enforces minimum spacing;
3. fetches one bounded market snapshot;
4. requires a new snapshot ID;
5. requires strictly advancing observation time;
6. burns that attempt before cognition so a failed evaluation cannot be retried
   indefinitely against the same observation;
7. invokes the existing canonical M15B agent exactly once.

The next paper decision therefore requires fresh market evidence.

## Android production binding

`AndroidPlatformRuntime` now exposes
`createProductionReadOnlyMarketDataSource(...)` and
`createProductionPaperTradingEpisodeRunner(...)`.

The latter captures the existing `VN97PaperTradingAgent`, so intelligence still
flows through the same activated VN97 model, typed cognition adapter, cognition
loop, optional existing memory, and M15A deterministic risk authority.

The app declares `android.permission.INTERNET`, while
`android:usesCleartextTraffic="false"` remains unchanged.

## Regression contract

`M15CMarketDataEpisodesTest.kt` covers HTTPS-only endpoint policy, rejection of
URL credentials, source-ID binding, symbol allowlisting, stale/future
observations, stale quotes, malformed UTF-8, byte bounds, minimum episode
spacing, fresh snapshot enforcement, strictly advancing observation time, and
bounded episode attempts.

APK compilation remains the Android integration gate.

## Security and trading scope

M15C is paper simulation only. Market-data network access is read-only and never
implicitly grants broker or live-money capability. Any future live-money route
must be a separate M6 deny-by-default capability with explicit user
authorization, exact account/broker scope, risk limits, revocation, durable
receipts, and no reuse of paper-trading authority.

## Next milestone
